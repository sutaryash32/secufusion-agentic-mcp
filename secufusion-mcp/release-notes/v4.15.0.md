## Summary
Brings the useful parts of the sfn-code-reviewer into this MCP: a no-model quick check for every push, an 81-rule catalog, adversarial and cross-model verification, deterministic finalizing (stable ids, floors, suppressions, delta, gate), SARIF and HTML reports, a command line (`sfn-ci`) with a pre-push hook and pipeline templates, a live-schema snapshot, a dependency vulnerability audit, release readiness, an eval corpus and metrics. 17 new tools (122 in all). No breaking changes.

## Added
- `run_quick_check` and `sfn-ci quick-check` / `pre-push` / `install-hook`: pattern checks with no model for applied migrations (any framework), mapped columns with no migration, committed credentials, SQL by concatenation, mutating endpoints without `@PreAuthorize`, flags that default on, unsafe DDL, floating versions, unpinned Dockerfile bases, pipelines that skip tests, tests that cannot fail and the web-ui rules. The hook fails open and never overwrites a hook that is not ours.
- `get_rule_catalog`: 81 rules from `rules/shared/*.md` (security and tenancy, database, contracts and Kafka, runtime, tests, dependencies, web-ui, history) with per-repository notes in `rules/repos/`; a workspace adds or overrides rules in `.secufusion/rules/`. New to the review: DB-008 to DB-011, SEC-004, 006, 010, 016, 017, 018, CON-006, CON-011, RUN-004, RUN-005, DEP-001 to DEP-009, WEB-001 to WEB-011, TST-004 to TST-008.
- `verify_findings` (adversarial; `mode: cross` through a second provider), `merge_review_runs` (consensus), `finalize_review_findings` (stable ids, floors, dated suppressions, noise cap, verdict, delta since the last review, gate), `findings_to_sarif`, `render_review_report`, `suggest_reviewers`.
- `snapshot_db_schema` and `lookup_db_schema` (read-only live PostgreSQL metadata), `audit_dependencies` (changes, major upgrades, OSV lookup behind `allow_network`), `check_release_readiness`, `get_review_metrics`, `get_engine_status`.
- `run_quick_eval`, `load_eval_cases`, `draft_eval_case_from_fix` and the eval corpus (12 cases, 6 judged by the quick check).
- `SFN_ENGINE` / `SFN_VERIFY_ENGINE` (anthropic or openai): engines for `sfn-ci` only, so a pipeline or hook can run the review where there is no editor. Inside the editor the review always uses the model you are logged into; the judgment protocol has no engine path.
- `ci/azure/sfn-review.yml`, `ci/azure/release-check.yml`, `ci/github/sfn-review.yml`; `sfn-ci` binary.
- `/sfn-review` STEP 1D (mechanical first, rule catalog, live schema, dependencies), adversarial verification in PASS 22, and machine-readable outputs in STEP 5.
- `benchmark_delivery`: 73 checks (real git repositories, fake provider servers, the command line).

## Changed
- The Kafka topic table in `AGENTS.md` (both copies) is stamped as verified against the code on 2026-10-23. Checking it against every `@KafkaListener` and `send` showed this table was right and the sfn-code-reviewer's was stale (no `sfn-policy-api`; `policy-events` has no live consumer because its listener is commented out; `extension-approval-decided` has two consumers).
- `verify_findings` cross mode is a second opinion you supply as `judgment`; without one it is answered by the logged-in model and says it is not independent.
- `score_review_run` accepts `rule_any_of` in an expectation.
- Severity floors lift only CONFIRMED findings: a floor never invents evidence.
- The tool count is 122.

## Fixed
- `AGENTS.md` and the rule catalog no longer disagree about which services take part in the Kafka topics.

## Breaking changes
None. The headless review and the vulnerability lookup are off unless you turn them on; both send data to a third party when you do.
