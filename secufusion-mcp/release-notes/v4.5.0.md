## Summary
The shared agent instructions now give every document exactly one home. Decisions and lessons go to `.mcp/` through `record_project_knowledge`, work-item artifacts go to the task folder, and repository files are touched only as the specification says, so the agent can no longer scatter copies of a document across repos or overwrite files the MCP generates.

## Added
- "Artifact placement, one home per document" in the shared `AGENTS.md`, with a type-to-home table and nine rules: search before you create, one source of record, `supersedes` instead of forked copies, never write a file an MCP tool generates, ask when a user-given path does not name a repo, update every reference on a move and search for the old path, a one-line preflight before each write, `log_file_touched` for every file, and a closing table (`path | home | committed? | referenced by`).
- `/sfn-spec`, `/sfn-code` and `/sfn-review` each point at the rule. In the review, a decision or lesson it surfaces is offered to `record_project_knowledge` rather than written as a file, and review notes go to the task folder.

## Changed
- ADRs, lessons learned, known exceptions, patterns and operational constraints are knowledge: they belong in `.mcp/` (saved `proposed`, accepted only by a person), not in the task folder or a service repo.
- Hand-written task documents carry a `.draft` suffix. The reviewer persona's deliverables are now `ado-comment.draft.md` and `pr-comment.draft.md` in the task folder (they were `ado-comments.md` and `pr-comment.md`).
- Documents, configuration, CI and environment files in a service repo are not created or changed without an explicit user instruction.

## Fixed
- Files placed in a repository the user never chose (for example docs written into the one repo that happened to have a `docs/` folder when the workspace root is not a repo).
- A hand-written `pr-summary.md` being overwritten by the MCP's own generated file; every generated filename (`spec.md`, `pr-summary.md`, `spec.json`, `decisions.json`, `progress.json`, `files-touched.json`, `scenarios.json`) is now explicitly off limits.
- Files created without being logged on the task, which left the generated PR summary incomplete.
- The same decision stored in several places (task folder, repository, PR text).

## Breaking changes
None. No tool was added, removed or renamed. The reviewer persona's two deliverable filenames changed (see above); nothing in the server depends on them.

## New tools
None.
