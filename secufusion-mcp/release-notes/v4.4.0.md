## Summary
`/sfn-review` is now spec-aware and experience-aware as well as product-aware. Before it reads the code it loads the specification the change was built against, the project's product knowledge and the engineering experience from earlier tasks, and it reviews conformance to the whole specification.

## Added
- Spec-aware Step 0: the review loads the specification (`spec_status`, `spec.md`, requirement, plan, intent, recorded decisions) before reading the code. With no work item given it looks for one from the branch name, recent commits or a task search and offers the match; with no specification it says so and never invents one.
- Specification conformance in PASS 6, beyond acceptance criteria: scope (`FINDING 6C`), recorded decisions (`6D`, a contradicted user decision is a BLOCKER), assumptions and unknowns the spec carried that the code now relies on (`6E`), and whether the spec's root cause and impacted services are supported by the code.
- The review also asks whether the specification itself contradicts recorded product knowledge, raised as a finding about the spec.
- Engineering experience is loaded as the lowest-trust memory (`get_engineering_experience`, `find_experience_conflicts`): a hint about where to look, never a rule, never overriding a current `.mcp/` entry.
- The report names the specification reviewed (work item, gates passed, acceptance criteria) and the experience consulted.

## Changed
- Step 0 keeps three memories apart with different authority: product knowledge (FACT about the product), the specification (FACT about intent), engineering experience (hints).
- Step 1B draws hypotheses from spec deviations (unexpected files, uncovered criteria, assumptions turned into behavior, contradicted decisions, scope growth) as well as from the code.
- PASS 6 now triggers whenever a specification was found, not only when a task folder has `spec.json`.
- The reviewer persona and README describe the spec-aware and experience-aware behavior.

## Fixed
- Lessons recorded through `record_engineering_experience` were written but never read by the review; the review now consults them, with provenance and freshness checks.

## Breaking changes
None. No tool was added, removed or renamed; the review accepts the same arguments.

## New tools
None.
