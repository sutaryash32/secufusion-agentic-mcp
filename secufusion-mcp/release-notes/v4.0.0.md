## Summary
Breaking release. The workflow becomes `init -> spec -> code -> review`, project knowledge moves into the repository (`.mcp/`), review gains diff-quality checks, and release notes become change-driven.

## Added
- `/sfn-spec` replaces `/sfn-explore` and `/sfn-plan`. It ends in a generated Implementation Specification (`generate_spec_document`); `/sfn-code` refuses to start without it.
- Hard gates enforced by the server: philosophy, intent, classification, requirement, plan, review. Judgments are recorded as validated verdicts; decisions only a person can make stop the work until they answer.
- Project Intelligence Layer: project knowledge under `.mcp/` with `proposed` versus `accepted` trust and a mandatory source.
- `/sfn-review` PASS 10 (`check_diff_quality`): line-ending conversions, mixed endings, whitespace and formatting rewrites, reordering, encoding changes, files outside the specification. A HIGH finding blocks approval. `normalize_line_endings` restores a file to its own style.
- Change-driven release notes (`generate_release_notes`): delta first, snapshot second, written to `.mcp/release-history/`.
- Ticket identity preserved (`BUG-1230` stays `BUG-1230`) via `resolve_work_item_ref`.
- Interactive exploration with static, clearly-marked UI references.

## Changed
- The architecture map now comes from `/sfn-init`; blast radius is part of `/sfn-spec`.
- The package no longer ships `scripts/.secufusion-*.json` or developer benchmark scripts.

## Fixed
- Line-ending and formatting noise is now detected before it reaches a pull request.

## Breaking changes
`/sfn-explore` and `/sfn-plan` no longer exist; use `/sfn-spec`. `/sfn-code` requires the Implementation Specification.

## New tools
`check_diff_quality`, `discover_ui_patterns`, `generate_release_notes`, `generate_spec_document`, `generate_static_ui_reference`, `get_design_context`, `get_project_knowledge`, `load_project_knowledge`, `manage_exploration`, `normalize_line_endings`, `record_project_knowledge`, `resolve_work_item_ref`, `set_knowledge_status`, `spec_status`, `verify_against_spec`.
