## Summary
After an approved review, `/sfn-review` now offers a full set of post-review documents: the ADO comment, the PR description, the ADR and a new design investigation record that preserves why a piece of work ended up the way it did. Each document keeps its one home and none duplicates another.

## Added
- Design Investigation Record (`investigation.draft.md`, in the task folder): a permanent document for a future engineer who was not involved. It covers the problem discovered, how it was investigated, assumptions proven wrong, the architectural requirements that followed, the original architecture, failure scenarios, the analyses actually performed, the options evaluated (accepted or rejected, and why), the final architecture and its rationale, remaining risks, release blockers, open questions and references.
- The ADR path in the review's post-verdict documents: an architecture decision is recorded once in `.mcp/adr/` through `record_project_knowledge` (saved `proposed`), searched for first, and superseded rather than copied when it changes.
- `/sfn-review` offers the full set (A) of ADO comment, PR description, ADR and investigation record, each only when it applies.

## Changed
- The post-review documents are produced in a fixed order: ADO comment, PR description, ADR, then the investigation record.
- The investigation record is built only from recorded evidence (requirement, decisions, spec, the review's reasoning trace and findings, the developer's answers). Where the reasoning was not captured it says "not recorded" and does not reconstruct a journey.
- If a repository path is requested for the investigation record, the placement rule applies: the agent asks which repo when the workspace has several or the root is not a repo, and copies the file with a `Source of record:` first line, leaving the task-folder copy canonical.

## Fixed
- Design reasoning (rejected options, disproved assumptions, release blockers) had no permanent home and was lost once the PR merged; it is now preserved next to the work item and, on request, in the repository.
- The risk of a second PR summary or a second ADR being created for the same work: the investigation record is explicitly forbidden from duplicating either and links to them instead.

## Breaking changes
None. No tool was added, removed or renamed.

## New tools
None.
