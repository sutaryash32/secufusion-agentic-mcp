## Summary
ADRs are now written as engineering design narratives, with the title and executive summary first and the machine metadata at the end of the file, and `/sfn-init` records the platform's Device vs Machine terminology by default so every project starts with it.

## Added
- ADR format standard. An ADR opens with `# ADR-NNNN: <Decision Title>` and a one-sentence summary, never with metadata or YAML-looking fields. The required structure is a Decision Snapshot (Problem, Decision, Outcome, Status, Related Work), Executive Summary, Context, Problem Statement, Investigation Summary, Options Considered, Decision, Consequences (Benefits, Trade-Offs, Risks, Future Reconsideration Criteria), Verification and References, so the first page answers what the problem was, why it mattered, what was chosen and why.
- `record_project_knowledge` refuses an ADR that begins with metadata or lacks the required structure and lists exactly what is missing. The tool writes the title heading itself and replaces a heading the body supplies.
- Platform defaults: `load_project_knowledge` accepts `seed_defaults`, and `/sfn-init` passes it by default. It records the MCP-shipped Device vs Machine terminology into `.mcp/architecture/` as a `proposed` entry whose source says it came with the MCP.
- A new ADR template in `.mcp/templates/adr.md` in the same layout.

## Changed
- ADR metadata (`id`, `title`, `status`, `tags`, `applies_to`, `source`, `date`, `supersedes`) is stored in a trailing `<!-- mcp:entry ... -->` comment, invisible when the Markdown is rendered. The loader reads front matter at the top (all categories, and every existing entry) or the trailing block (ADRs).
- `set_knowledge_status` keeps the readable **Status** line in the Decision Snapshot in step with the recorded status, and changes nothing else.
- Retrieval shows the readable ADR, summary first.
- The repository's own ADR-0001 is rewritten in the new format, and its status paragraph now names the roadmap areas instead of using numbers that did not match its list.
- The reviewer persona and the README describe the ADR standard and the platform defaults.

## Fixed
- ADRs opened with raw metadata, so a reader had to dig through machine fields to find the point of the document.
- Every project had to record the Device vs Machine terminology by hand; a fresh `.mcp/` started without it.

## Breaking changes
None. Existing entries, including ADRs with front matter at the top, load unchanged and other categories keep front matter. A new ADR that does not follow the standard is now refused, so a script that creates ADRs with a free-form body must supply the structured body.

## New tools
None.
