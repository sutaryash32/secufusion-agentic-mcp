## Summary
`/sfn-code` now enforces code quality while it writes (SOLID, DRY, code placement, formatting) and `/sfn-review` checks the same things when it reads, with a new fix-history regression pass and protected severities. `/sfn-review` grows to 28 passes (PASS 0 to PASS 27). No new tools and no breaking changes.

## Added
- **`/sfn-code` Phase 3A, Code Quality**: four checks after every file: SOLID (SRP, OCP, LSP, ISP, DIP with SecuFusion examples), DRY (search before writing, extract duplicated guards, tenant-id extraction, repository sequences and error strings), code placement (never append to the end of the file by default), and formatting (copy the nearest neighbour, `check_diff_quality` after each file).
- **PASS 25, SOLID Violation Detection**: BLOCKER for an SRP violation that shares a transaction boundary or an OCP violation that edits a stable method; WARNING for ISP and LSP; SUGGESTION for DIP on internal classes.
- **PASS 26, DRY & Simplification**: duplicated guards and tenant extraction, repeated `getActingTenantId()` calls, code appended to the end of the file.
- **PASS 27, Fix-History Regression Check**: finds past fixes through `git log --follow` (with a `smart_search` fallback), `.rejected-patterns.json` and `decisions.json`; adds a `FIX-HISTORY` subsection to the card; adds a regression line to BEFORE YOU MERGE.
- **PASS 22 severity floors**: tenant predicate missing, direct JWT caller read, unhandled Kafka publish after a committed write, REGRESSION on `Basis: FACT`, `defaultUser` / `isAdmin` corruption. A floor holds as BLOCKER only for Class A with `Basis: FACT`; INFERENCE and Class B/C are WARNING. Floor findings cannot be suppressed.
- **PASS 22 expiring suppressions**: a suppression in `decisions.json` is valid for 30 days from `suppressed_on`, `acknowledged_on` or `date`; with no date it is honoured and flagged.
- Report categories `SOLID-VIOLATION`, `DRY-VIOLATION`, `PLACEMENT`, `REGRESSION`.

## Changed
- **PASS 22 ordering**: it runs after all finding passes (PASS 0 to PASS 27) and before the report is written, instead of "last among all passes".
- **Output contract**: a finding card has three required subsections (PROBLEM, IMPACT, FIX); a PASS 27 card may add FIX-HISTORY after FIX.
- **`/sfn-code` Phase 1** also loads `.rejected-patterns.json` (task-level patterns win), and progress is recorded per acceptance criterion with `completed_acs` and `pending_acs`.
- **Coder persona**: optimization applies only inside the spec's file list; the architectural reasoning comment is required only for non-obvious code; phases are labelled `EXEC-Phase 2` and `EXEC-Phase 3`.
- Pass-range references in `/sfn-review` now read PASS 0 to PASS 27.
