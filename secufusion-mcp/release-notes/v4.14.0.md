## Summary
One new tool, `check_applied_migrations` (105 in all): a deterministic, framework-neutral guard that an applied migration is never edited, renamed or deleted, and that a new migration does not reuse or undercut a version. It closes the one migration rule that the sfn-code-reviewer quick check had and `/sfn-review` did not. No breaking changes.

## Added
- **`check_applied_migrations`**: compares the change with the base branch and reports, with no model, an applied migration that was edited, renamed or deleted (BLOCKER), a new migration that reuses a version already taken (BLOCKER), and one numbered below the head of its series (WARNING). Flyway-style versioned SQL (repeatable `R__` migrations may change), Rails, Django, Alembic, EF Core (the model snapshot is ignored), Prisma and generic `migrations/` folders; versions are compared inside one series, never across services; committed, staged, unstaged and untracked changes are all seen.
- `/sfn-review` PASS 0 check 0F (applied migrations are immutable), with the `DEPLOYMENT` report label.
- `benchmark_migration`: 17 checks on real git repositories, one framework after another.

## Changed
- `/sfn-review` PASS 0 triggers on a migration file of any framework, not only `.sql` and Java entities.
- The tool count is 105.

## Fixed
- `agents/AGENTS.md` claimed a pre-PR check was "automated in `run_pre_pr_checks`", a tool that no longer exists. It now points at PASS 0 and `check_applied_migrations`.
