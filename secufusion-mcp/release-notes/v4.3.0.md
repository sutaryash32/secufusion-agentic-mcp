## Summary
The release file that `/sfn-init` writes (`v<version>.md`) now also says what the new MCP version itself brings, for every version the project skipped, in addition to what changed in the project.

## Added
- A "What this MCP version brings" section in the generated release notes, right after the Executive Summary. It lists every bundled MCP release after the project's previous MCP version, up to the new one, newest first, with each release's summary, added, changed, fixed, breaking changes and new tools.
- The MCP ships one release-notes file per version (`release-notes/vX.Y.Z.md`) for 4.0.0, 4.1.0, 4.2.0 and 4.3.0.
- A `mcp_release_info` option on `generate_release_notes` (default true) to switch the section off.

## Changed
- `/sfn-init` instructions tell the agent to keep `previous_version` accurate and not to rewrite that section.
- A release now requires its own release-notes file: a test fails if `release-notes/v<package version>.md` is missing or has an empty section, so a version cannot be bumped without a summary.

## Fixed
- A release file written by `/sfn-init` carried only project changes; the information about the MCP release that produced it existed only in the README. It is now in the file.
- When a version has no bundled notes, the release file says so instead of omitting the section silently.

## Breaking changes
None. No tool was added, removed or renamed; existing parameters are unchanged and the new one is optional.

## New tools
None.
