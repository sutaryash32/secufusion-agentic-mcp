## Summary
Fourteen new tools (104 in all) that replace guesswork in the review with mechanical evidence, in any language: Java, Kotlin, TypeScript, JavaScript, Python, C#, Go, Ruby, PHP and SQL. Findings must cite code that exists, tenant isolation is scanned deterministically, lifecycle invariants are model-checked, and the reviewer can now be measured and routed. No breaking changes.

## Added
- **Two review modes** for `/sfn-review`: Mode 1, Existing Task Review (a work item whose task folder holds a specification) and Mode 2, Context Discovery Review (no task, specification or acceptance criteria). `discover_review_context` takes the `work_item` as written and decides the mode deterministically (with the reason, what Mode 1 would be missing, and a task that may explain the diff, proposed and never adopted silently); a type conflict with an existing folder is an identity conflict; Mode 2 switches to Mode 1 when a task is confirmed. The report header names the mode.
- **Context discovery mode** (Mode 2) for `/sfn-review` (a review with no task id, requirements or acceptance criteria): seven phases (assess, infer the intent, gap analysis, draft task context, reconstruct, review, capture knowledge) and a golden rule: recover context before requesting it. **`discover_review_context`** returns the context completeness report (each source found or missing, a coverage score), the work-type hint with its evidence and any ambiguity between the branch and the commits, the references seen, task folders that may explain the diff (candidates, never adopted silently), earlier draft contexts, and a provisional reference. **`record_draft_task_context`** keeps the temporary task context (BE-, FE-, FS-, EXT- or INFRA-TASK-Dnnn; the D keeps it apart from real ticket numbers) with every entry CONFIRMED (needs the developer's words), INFERRED (needs its evidence) or UNKNOWN, refuses to store inferred information as confirmed, never touches the task registry, and is found again by the next review through the files it explains. A finding that rests on an inferred intent is at most a WARNING and a question.
- **`reason_about_intent`**: makes the inference a reasoning task rather than a template. It hands the model the diff, the commits, the candidate tasks and what the product's own memory says about this change (the invariants and decisions that apply, the authority fields the diff writes, the lifecycle paths it touches), and asks for competing hypotheses, a product-aware reading, and an investigation (what it read, what it would read next). The tool verifies every cited line against the code, caps an unsupported hypothesis at 40, subtracts 25 for a verified contradiction, treats a runner-up within 10 points as ambiguity, sets the confidence from the evidence rather than the claim (HIGH 80+, MEDIUM 50 to 79, LOW below 50), and applies the context protocol to the questions (at most two optional ones at HIGH, three at MEDIUM, five at LOW, and none that are not shown to be non-inferable). `discover_review_context` also reports the invariants that apply to the diff, the recorded authority fields it writes and the lifecycle paths inside the files it changes. Confidence is logged at each stage (inferred, confirmed, final) in the draft, so it can be measured whether discovery improved understanding.
- **Context sufficiency protocol** (Rule 0b in `AGENTS.md`), run first by `/sfn-init`, `/sfn-spec`, `/sfn-code` and `/sfn-review`: inventory what is available, state the objective, sort what is needed into KNOWN, INFERRED and UNKNOWN, recover from the repository before asking, ask only what is critical, not inferable, not discoverable and blocking (as "I believe X because Y; confirm or correct"), state the confidence (HIGH proceed, MEDIUM proceed and document assumptions, LOW ask the minimum), and keep facts, recovered context and assumptions apart. It governs missing context, never missing decisions: product choices stay the user's. The report's ASSUMPTIONS section now opens with the context confidence and marks each assumption INFERRED or ASSUMED.
- **`build_claims_ledger`**: the story as claims, plus IMPLIED claims (accepted invariants and decisions from `.mcp/`) and SILENT claims (lifecycle paths the story never mentions), each judged against the code with verified citations; the diff is mapped back to the claims (written-not-built, built-not-written).
- **`build_edge_matrix`**: product-aware edge hypotheses ranked by risk (project knowledge, code lifecycle paths and authority consumers, the reviewer's own hypotheses, then a generic baseline). `reason_top` has the model reason about the top cells through the judgment protocol; every citation in its verdict is verified and nothing is stored.
- **`check_platform_facts`**: the facts in `AGENTS.md` (topic table, named paths, services) checked against the code; contradictions carry file:line.
- **`validate_finding_evidence`**: confirms each finding's file (inside the workspace), line and quoted code; drops unsupported findings; weighs an optional proof test (PROVEN, REFUTED).
- **`check_tenant_flow`**: unscoped data access, lookups by id alone and unguarded request-sourced tenant ids, with per-language profiles, learned tenant-owned entities and global-scoping awareness.
- **`check_lifecycle_model`**: bounded model checker for lifecycle invariants, sequential and concurrent (check-then-act interleavings, locks), with the shortest counterexample.
- **`generate_invariant_checks`**: violation query, DDL draft and test skeleton per invariant; postgres, mysql, sqlserver; eight test languages; injection-safe.
- **`analyze_mutation_report`**: surviving mutants on changed lines from PIT, Stryker, Infection or a generic report.
- **`score_review_run`**: recall, precision and per-pass advice from eval cases and review runs.
- **`route_review_passes`**: risk-scaled pass selection with reasons, skips and parallel groups.
- **`get_fix_history`**: fix-like commits for a file or line range plus rejected patterns and decisions.
- `/sfn-review` STEP 1C (routing) and a LANGUAGE-NEUTRAL REVIEW table; `tests/instruction-lint.mjs`; `benchmark_sharper` (60 checks across nine languages).

## Changed
- PASS 1, 15, 22, 24, 27 and the zombie-state lens call the new tools; PASS 6 gains an optional mutation-testing step.
- `/sfn-code` Phase 3A applies SOLID and DRY in the file's own language and runs `check_tenant_flow` on what it wrote.
- PASS 22 runs the evidence gate before the noise filter.
- `/sfn-review` gains STEP 0.2g (platform facts) and 0.2h (claims ledger); PASS 19 reports the ledger's gaps and PASS 20 starts from the edge matrix. `/sfn-spec` checks whether the story matches reality (Step 3) and enumerates edges before the plan is final (Step 5). `/sfn-code` self-reviews with the ledger.
- The tool count is 101.

## Fixed
- A line-ending or whitespace finding had no report label, so reviews filed it under `PLACEMENT`. There is now `DIFF-QUALITY` (and `BEHAVIOR-CHANGE`, `MERGE-REGRESSION`, `PRIVACY`, `DEPLOYMENT`, `RESILIENCE`, `ARCHITECTURE`); `PLACEMENT` means only code put in the wrong place inside a file.
- PASS 11 promised a "PRODUCT & PRIVACY FIT" table that the compact report had no place for, so reviews improvised one. The five answers now end the PASSED section, and UNVERIFIED or CONCERN answers are repeated in NOT EXAMINED.
- A review could lower a rule-based BLOCKER because the developer asked. Severity is now set by evidence and rules, not by request: a disagreement without new evidence is recorded as `Developer position:` on the card, with an offer to record an accepted known exception.
- The report now has a slot for everything that used to be loose prose: records the review wrote (a footer line) and a verdict gate that could not run (NOT EXAMINED). The closing text is no longer printed twice after a rejection, and the re-run line appears only when the verdict is not APPROVED.
- PASS 4 listed Kafka topics that appear nowhere in `AGENTS.md` or the code; it now uses `extract_event_topics`.
- The middle verdict had two names (APPROVED WITH CHANGES and APPROVED WITH COMMENTS); it is APPROVED WITH CHANGES everywhere.
