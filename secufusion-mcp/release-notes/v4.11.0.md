## Summary
`/sfn-review` gains six new passes (PASS 19 to PASS 24, bringing it to PASS 0 through PASS 24), six existing passes are rewritten around SecuFusion's real services, tables and invariants, and the final report moves to a compact, standardized card format with a verdict banner, ready-made ADO and PR comments, and a fixed section order.

## Added
- **PASS 19, Spec & Product Cross-Examination**: for every acceptance criterion, finds the implementing `file:method:line` and reasons about whether the intent is met, partly met, inverted or missed; also checks the PR description against the code.
- **PASS 20, Adversarial Edge-Case Simulation**: traces null or empty input, mid-transaction failure, concurrent requests, downstream timeout and a cross-tenant probe through each new or changed entry point.
- **PASS 21, Cross-Stack Contract Parity**: finds every consumer of a changed REST shape, status code, error envelope or Kafka payload (frontend, other services, extension) and reasons whether each still works.
- **PASS 22, Ruthless Noise Filter**: a self-check before output that removes cosmetic, test-covered or pre-existing-code findings and keeps only those with WHERE, WHAT, WHY and CONTEXT.
- **PASS 23, Blast-Radius & Side-Effect Awareness**: builds the dependent graph of a change and checks the platform invariants (`defaultUser`, `isAdmin`, `tenant.email`, Kafka topics, shared utilities, authorizers), including the "guard added in one method, bypassed in another" pattern.
- **PASS 24, Nice-to-Have & Follow-Up Triage**: advisory items (database constraints for code invariants, error-message clarity, eligibility APIs, accessibility, partial-success resilience, guard symmetry).
- **Standardized report**: header, verdict banner (shown twice), blockers, warnings, nice-to-have, passed, assumptions and before-you-merge, with PROBLEM / IMPACT / FIX cards and a fixed category list; ADO and PR comment drafts are generated from the same findings.

## Changed
- **PASS 2 (N+1)**: names the known hot paths in `UserService`, `GroupService`, `EventsService` and `TenantService`, and separates BLOCKER from WARNING cases.
- **PASS 3 (missing index)**: names SecuFusion's hot query patterns (`fk_tenant_id` composites, `defaultUser` / `isAdmin` flags, device identifiers, mapping tables).
- **PASS 4 (Kafka safety)**: blocking calls inside listeners, unhandled publish results after a committed write, payload changes against all consumers, dead-letter and idempotency.
- **PASS 5 (architectural patterns)**: authorization on every endpoint, caller resolution through `tenantContext`, transaction boundaries, external-call safety, logging and secrets.
- **PASS 9 (architectural suggestions)**: limited to five platform-specific, non-blocking suggestions.
- **PASS 18 (future maintainability)**: invariant documentation, lock-order visibility, test-gap awareness, knowledge capture.
