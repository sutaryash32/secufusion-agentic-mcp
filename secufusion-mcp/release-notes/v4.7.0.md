## Summary
The PR summary is now an engineering change summary that a reviewer who has never seen the work item can follow, and the philosophy gate must show the evidence behind any verdict other than a clean pass.

## Added
- `generate_pr_summary` tool: writes `pr-summary.md` as an engineering change summary with twelve sections: the problem, how it was investigated, the root cause, the architectural options evaluated, why the design was selected, how the final design works, the issues resolved (acceptance criteria), behavior before and after (including multi-instance behavior where relevant), tests executed and results, remaining risks and release considerations, business impact, and the files changed as a reference at the end.
- The summary is assembled from recorded state (requirement facts and root cause, the options put to the user, plan, decisions with rationale, scenarios, recorded test runs since the task began, gate ledger and review verdict). Anything the record does not hold says "Not recorded"; nothing is invented.
- An optional `narrative` for what only the author knows (options weighed and why each was accepted or rejected, behavior before and after, tests actually run, remaining risks, business impact). It is saved beside the task as `pr-narrative.json` and shown as Author notes.
- A `reasoning` field on the philosophy verdict: evidence-backed points naming the service, topic, entity, golden rule or rejected pattern a verdict rests on. It is required for ADVISORY, FAIL and BLOCKED, and shown in the gate's report.

## Changed
- `manage_task action=complete` writes the same engineering change summary (re-rendered with the saved narrative) instead of a list of acceptance criteria, files, decisions and scenarios.
- `/sfn-review` writes the PR summary with `generate_pr_summary` before completing a task, supplying the narrative only from what the work actually established.
- `pr-narrative.json` joins the file names an MCP tool generates and the agent must never overwrite.
- The philosophy rubric asks for named evidence and rejects "looks risky" as reasoning.
- The tool count is now 74.

## Fixed
- The generated PR summary documented what changed but not why: it carried no problem statement, root cause, investigation findings, rejected alternatives, risk analysis or business impact.
- A rich hand-supplied summary being replaced by the generic one when the task was completed.
- A non-passing philosophy verdict that gave no visible reasoning for the person acting on it.

## Breaking changes
None for tools, parameters or commands. `pr-summary.md` has a new layout: anything that parses the old headings (Acceptance Criteria, Files Modified, Architectural Decisions, Test Scenarios) must be updated. A saved ADVISORY, FAIL or BLOCKED philosophy verdict without `reasoning` no longer validates if replayed.

## New tools
`generate_pr_summary`.
