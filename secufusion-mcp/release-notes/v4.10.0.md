## Summary
`/sfn-review` becomes a product and architecture reviewer that argues business consequences, not dependencies. Stories about ownership, roles, admin, tenancy, permissions and lifecycle run a pessimistic mode built on entity contracts, a feature model, a field impact model, prior decisions, an invariant catalog and a confidence score; four lenses close misses a client review exposed; and a calibration suite measures whether the review would have written the client's comments, including from Azure DevOps pull request threads.

## Added
- Pessimistic, product-centric review mode (automatic for ownership, role, admin, tenancy, permission and lifecycle stories, or on request): the change in business terms and the invariants before any code, entity contracts (ownership, authority, lifecycle, consistency and source of truth, audit, dependencies, tenancy, UI, operations), eleven lenses plus zombie states, UI failure paths, historical data, copy divergence and support operations, an authority drift report, support-ticket simulation, a ten-question completeness check, and a hostile principal architect pass. Every finding carries a reasoning chain from entity to client impact, with a link written UNKNOWN where it cannot be shown.
- `check_entity_impact`: the platform-wide inventory of what depends on an entity, with authority coupling (a flag read inside an authorization decision) and ranked consumers.
- `check_invariant_enforcement`: how the field behind an invariant is protected: database constraint, lock per writing method, or only a check before the write.
- `build_feature_model`: the work item family, the entities, the lifecycle transitions that exist and the ones with no path, capability dependencies, the cross-service graph and a transition-by-contract review matrix, built before the diff is judged.
- `build_field_impact`: every consumer of a field classified by what it does with the value, with dotted attributes (`tenant.email`) and one hop of derived-value tracing into the decision it feeds.
- `check_ui_gating`, `find_endpoint_consumers`, `check_service_ownership`, `trace_parent_cascade`: who sees an action versus who may execute it; every caller of a changed endpoint through URL constants and wrappers; which service owns a table and which others write it; what a parent's delete or deprovision does to its children.
- `check_decision_alignment` and the decision registry (`.mcp/decisions/`): recorded decisions the change touches, with signals; the reviewer judges ALIGNS / VIOLATES / PARTIALLY ALIGNS / UNVERIFIED. `get_relevant_invariants` and the invariant catalog (`.mcp/invariants/`): invariants classified CONFIRMED / PROPOSED / VIOLATED / NOT DEMONSTRATED from status and real enforcement evidence.
- `score_review_confidence`: HIGH / MEDIUM / LOW confidence with hard caps (stale review, no cross-service scan, open decisions, UNKNOWN completeness answers), so "no findings" is not read as "trustworthy".
- Post-review change detection: a review is STALE when files change after the verdict; `manage_task action=complete` is refused until the delta is reviewed.
- Calibration against client reviews: `calibrate_review` (seal your findings, then reveal the client's comments; MATCH / PARTIAL / MISS), `prepare_unseen_pack` (the only input a calibration review may read: requirements, decisions before the client review, and the code at the commit the client reviewed), and `parity/tools/ado-fetch.mjs` (the client's Azure DevOps review threads as the answer key; the read-only token is typed into a hidden prompt and discarded). A MATCH needs the same entity, business consequence and unsupported state and a materially equivalent comment; every PARTIAL and MISS must name the failing reasoning step and the smallest improvement. Parity figures are reported only for a blind run on an unseen story; anything else reports counts.

## Changed
- The tool count is now 90.
- `/sfn-review` loads prior decisions and the invariant catalog before judging and reports DECISION ALIGNMENT, INVARIANT CATALOG and REVIEW CONFIDENCE.
- Knowledge categories gain `decisions` and `invariants`, with structured metadata (`ref`, `domain`, `fields`, `enforcement`, `write_paths`, `guardrail`, `decided_by`); `record_project_knowledge` accepts `meta`. Nothing is recorded as accepted without the user's own words.
- The authority drift report states the difference between what the new owner can do and what the previous owner can still do after a transfer.
- The package now ships `parity/README.md` and `parity/tools/ado-fetch.mjs`. Benchmark data holding client review material is not shipped.

## Fixed
- The enforcement map credited a CHECK constraint on a neighbouring column to the field being examined (a schema with a CHECK on the next column rated `created_by` as DB_ENFORCED).
- A review could finish with "no findings" and read as trustworthy with no cross-service scan, no concurrency analysis and open decisions behind it.
- A review of one task could miss its parent bug, sibling task and recorded decisions.

## Breaking changes
None for commands, existing tools or their parameters. A review of an ownership, role, admin, tenancy, permission or lifecycle story now does more work and reports more sections. `manage_task action=complete` now refuses a review that went stale.

## New tools
`check_entity_impact`, `check_invariant_enforcement`, `build_feature_model`, `build_field_impact`, `check_ui_gating`, `find_endpoint_consumers`, `check_service_ownership`, `trace_parent_cascade`, `check_decision_alignment`, `get_relevant_invariants`, `score_review_confidence`, `calibrate_review`, `prepare_unseen_pack`.
